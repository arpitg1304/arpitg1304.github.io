An Empirical Study of Data-Loading Bottlenecks (and Non-Bottlenecks) in Robotic Imitation Learning

Mrinal Jain1, Arpit Gupta2, Animesh Garg1 · 1Georgia Tech  2General Motors

TL;DR Faster data loaders don't shorten robot-policy training. Unindexed video seeking does lengthen it. We profiled end-to-end LeRobot training (ACT, SmolVLA) against a Rust data engine we built to be as fast as possible. The loader turned out not to be the bottleneck.

1–3.5%of each training step is spent waiting for data. Model compute takes the rest.
3.94×isolated loader speedup over torchcodec, but 324 s vs 326 s end to end, within noise.
5.6×slower training from PyAV's unindexed AV1 seeking: the one real bottleneck.

Forge

The robotics data toolkit and data engine.

Convert between every major robot-learning format (RLDS, LeRobot v2/v3, HDF5, Zarr, MCAP, rosbag) through a canonical Episode/Frame representation, so adding one reader gives you every writer instead of N×M converters. Score episodes on proprioceptive quality metrics (LDLJ smoothness, dead actions, gripper chatter), then register everything in a DuckDB catalog you can query with SQL, search semantically with SigLIP, and dedupe.

$ pip install forge-robotics
$ forge quality hf://lerobot/pusht

Robotics Agent Skills

Production robotics knowledge for AI coding agents.

General-purpose coding agents know ROS syntax but miss what matters in production: QoS compatibility, deterministic startup, bounded callbacks, sensor health and safe shutdown. Ten drop-in skills (ROS2, perception, testing, bringup, Docker, security, design patterns) for Claude Code, Cursor, Copilot and any agent that reads SKILL.md files.

ROS Time Machine

A dashcam for your robot.

A rolling in-memory ring buffer for every topic. When a trigger fires, it stitches the pre-event buffer to live post-event recording in a single MCAP bag. v2 adds semantic triggers: describe events in plain English ("the cup falls from the gripper") and a vision-language model watching a 1 fps feed decides what to save. The clip points back to when the event happened, so model latency costs nothing.
